- 新增 PUT /api/topics/{id}/title（空白标题 422，截断 512）；工作台排期行与
  灵感池行都加「改标题」按钮（prompt 改名即生效，生成时用新标题）。
- 排期幂等不受影响：合集幂等键看本周 existing 数量、主题模式按 evidence
  subtopic 去重，均不看标题。
- 测试：test_pillar 新增 [14]；p0/p1/p3 回归通过。

### 补丁 4：glm-4.7 生成偶发"不是合法 JSON (char 0)"

- 现象：HTTP 200 但 `json.loads` 报 `Expecting value: line 1 column 1 (char 0)`。
- 根因（最小真实调用验证）：glm-4.7 默认开思维链，且 reasoning 与正文共享
  max_tokens（completion_tokens_details.reasoning_tokens 可见）。v3 长提示
  让思考段变长，4096 额度烧完后正文为空串 → `json.loads("")` 正是 char 0。
- 修复：
  - _call_llm 检查 finish_reason=length / 空正文，明确报"被截断"并附
    max_tokens 额度说明（进重试逻辑，提示模型精简）
  - _parse_and_validate 容错：剥 markdown 围栏、截取最外层 {…}；错误信息
    带原文开头 repr 便于下次定位
  - 默认 LLM_MAX_TOKENS 4096→8192、LLM_TIMEOUT 60→120s（思维链产出慢）
- 测试：test_p1 新增 [9]（围栏/夹文字/空串）；p0/p2/p4/p5 回归通过。
- 备忘：bigmodel 支持 `thinking:{type:"disabled"}`（实测生效，reasoning=None），
  若后续想省 token 提速可在 _call_llm 加开关。

### 补丁 5：生成默认关思维链（用户拍板）

- _call_llm 对 glm 系模型下发 `thinking:{type:"disabled"}`（config
  LLM_DISABLE_THINKING，auto 默认；true/false 可强制，非 glm 供应商不带
  此参数）。产物是结构化 JSON 文案，思考段纯烧钱——实测同任务 324→23
  completion tokens，且杜绝"思考烧尽 max_tokens 致正文空串"一类故障。
- 回归 p0/p1/p5 通过。

### 补丁 6：生成后返回工作台状态不刷新（通病）

- 根因：浏览器 HTTP 缓存 + 后退缓存（bfcache）。生成跳文章页后返回 /，
  浏览器直接展示旧页面/旧 DOM，不回源——"最新生成"停留在旧状态。
- 修复：guard 中间件对 text/html 响应统一加 Cache-Control: no-store；
  base.html 加 pageshow(e.persisted) 时强制 reload（兜 bfcache 的 case，
  no-store 本身也会让多数浏览器不进 bfcache）。
- 测试：test_p1 新增 [10]；p0/p1/p2/p3/p5 回归通过。

### 补丁 7：封面图与文案同步（两段式封面上线）

- 需求：此前封面是纯色底 + 文字（版式 yml），画面与文案内容零关联。
- 方案（A3 敲定的两段式）：LLM 从标题/正文/标签归纳一句画面提示词 →
  GLM cogview-4 生成无字底图（3:4 → 864x1152 缩放到 1080x1440 画布）→
  imaging 原槽位叠印中文标题（文字区压半透明深色蒙层保对比度）。
- 新增 services/imagegen.py：cover_prompt（LLM 失败回退"标题+标签"确定性
  提示词）、generate_background（尺寸档自动匹配；LLM_MOCK / 无 key / 关开关 /
  任何接口错误 → None，绝不把 article 拖成 failed）。
- 接线：routes_topics 在事务外生成底图（慢速 IO 不占事务），透传
  xhs_adapter.render_assets → imaging.render_note_images（只封面吃底图，
  金句图仍纯色版式）。config 新增 CF_IMAGEGEN_ENABLED（默认 true）、
  GLM_IMAGE_MODEL（默认 cogview-4）、CF_IMAGEGEN_TIMEOUT_SECONDS。
- 真实验证：提示词"电影级写实风格，细腻光影层次，胶片颗粒质感…"与文案
  同步；cogview 出图 + PIL 叠字整链路通过。单张约 ¥0.06。
- 测试：test_p2 新增 [9]（mock 零联网/回退提示词/背景图改像素/蒙层压暗/
  金句图不吃底图）；p0/p1/p2/p3/p5 回归通过。

## P6 融合红狐 skill：标题打分 + 多平台改写

- 参考 redfox-community 的 xiaohongshu-rewrite / multi-rewrite /
  xiaohongshu-title-score 三个 skill 的方法论，融合为产品内功能（不打红狐
  付费接口，规律内化进模板由自有 GLM 执行）。
- 标题打分（xhs+title_score 模板，六维加权沿用红狐原版权重：主题匹配 15% /
  结构合规 20% / 利益清晰 25% / 情绪唤醒 20% / 稀缺性 15% / 合规 5%）：
  POST /api/titles/score {title, keyword?}，无状态不落库；等级按总分确定性
  推导（S≥9.0 / A≥7.0 / B≥5.0 / C）。文章页 ready 态新增「六维打分」卡片，
  展示总分/等级/六维明细/问题/建议/改写版标题。
- 多平台改写（xhs/rewrite + wechat/rewrite 模板）：POST /api/articles/{id}/
  rewrite?platform=…，以成文为源跨平台转换（公众号长文 ↔ 小红书笔记），
  铁律禁止新增原文没有的信息；落库与 generate 同语义（xhs 自动出两段式
  封面），meta.rewrite_from 溯源。文章页加「改写为另一平台」按钮。
- 重构：generate 落库段抽成 _persist_generation 供 generate/rewrite 共用。
- 真实验证：7.6→7.8 分 A 级，六维点评与建议合理（补数字、强动词、emoji），
  改写版标题三种风格可用。
- 测试：新增 tests/test_p6.py（种子/打分/改写链路/约束/页面契约/生成回归）；
  test_p3 种子断言随 P6 扩充；全量回归通过。
